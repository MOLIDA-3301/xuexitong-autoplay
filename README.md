# 学习通 自动连播 · 播完即停

一个 Tampermonkey 用户脚本。在学习通（`chaoxing.com`）课程章节页里自动播放视频、自动推进图文课件（PPT / 文档），一节播完自动进入下一节；全部任务点完成后停止并提醒你。

> 脚本只在你**已经登录**的浏览器里，操作**你自己有权访问**的页面。它不碰服务端、不绕过登录、不做任何鉴权伪造 —— 就是把「点播放、翻页、点下一节」这些手工动作自动化。

---

## 特性

| | |
|---|---|
| **视频自动播放** | 自动点播放按钮、自动静音（浏览器允许自动播放的前提）、被暂停或被切走自动恢复 |
| **课件秒过** | 图文节点（PPT / PDF / 屏阅阅读器）自动翻到末页，支持滚动式与翻页式两种渲染 |
| **视频 + 课件同节点** | 视频播完后**继续把本节课件推光**再跳走（v7 起），不会像早期版本那样把 PPT 掠过 |
| **目录驱动跳转** | 靠右侧章节目录定位与推进，四层跳转保险：目录下一项 → 未完成项 → 「下一节」按钮 → 改 URL |
| **播完即停** | 全部任务点完成（或无课可跳）后主动停止，改页面标题并弹出系统通知 |
| **实时悬浮面板** | 右下角可拖拽面板，三色指示灯 + 状态栏实时显示当前动作，随时暂停 / 跳节 / 调倍速 |

## 安装

1. 浏览器装 [Tampermonkey](https://www.tampermonkey.net/)（或 Violentmonkey）
2. 打开下面的链接，Tampermonkey 会弹出安装页，点「安装」：

```
https://raw.githubusercontent.com/MOLIDA-3301/xuexitong-autoplay/main/xuexitong-autoplay.user.js
```

如果 `raw.githubusercontent.com` 打不开，用 jsDelivr 镜像：

```
https://cdn.jsdelivr.net/gh/MOLIDA-3301/xuexitong-autoplay@main/xuexitong-autoplay.user.js
```

3. 打开学习通课程章节页，脚本自动启动

脚本的 `@updateURL` 指向 jsDelivr，后续有新版会自动提示更新。

### 三色指示灯（左上）

**一次只亮一颗，其余是暗点** —— 像红绿灯：

| 灯位 | 颜色 | 含义 |
|---|---|---|
| 最左 | 🔴 红（闪烁） | 已停止 / 出错 |
| 中间 | 🟡 黄 | 暂停 / 等待节点 / 检测到测验弹窗 |
| 最右 | 🟢 绿 | 正常运行（含「本节已完成」） |

### 状态栏（中间大字）

**文字说「正在干什么」，颜色说「跑得顺不顺」**，两者独立：

| 运行状态 | 文字效果 |
|---|---|
| 正常运行 | 五彩跑马（渐变横向流动） |
| 暂停 / 等待 | 黄色，静态 |
| 停止 / 出错 | 红色 + 微闪 |
| 本节完成 | 蓝色，静态 |

文字内容来自**动作状态机**：谁在干活谁打点，所以显示的是真实动作 —— `正在播放视频`、`正在划 PPT · 补推`、`正在跳转下一节`、`视频被暂停，正在恢复` …… 动作停了 9 秒没更新就自动降级，不会卡在过期状态。

### 按钮

| 按钮 | 作用 |
|---|---|
| `⏸ 暂停` / `▶ 继续` | 同键来回切。**挂起自动操作，进度全留** |
| `⏭ 下一节` | 当前节点立刻放行，去下一个待完成项 |
| `1.5x` | 倍速循环：`1 → 1.25 → 1.5 → 2 → 2.5 → 3` |
| `📋 诊断` | 一键复制诊断报告（日志、目录项、视频状态），排错用 |
| `✕`（右上角） | **真正停用脚本**，需刷新页面才能恢复 |

## 配置

脚本顶部 `CFG` 对象，改完保存、刷新页面即可生效：

```js
const CFG = {
  rate:         1.5,    // 倍速。1.5 是学习通官方允许的上限
  mute:         true,   // 自动静音（浏览器要求静音才允许自动播放）
  autoNext:     true,   // 播完自动前往下一节
  closePopup:   true,   // 自动关「请点击继续观看」这类防挂机弹窗
  keepAlive:    true,   // 被暂停 / 切走 / 假死就自动恢复
  skipNonVideo: true,   // 遇到非视频节点自动跳过
  tick:         1000,   // 轮询间隔 ms
  docStep:      2400,   // 课件推进间隔 ms
  docFast:      true,   // 课件秒过（连发手势 + End 键）
  docBoost:     12,     // 一次推进连发多少次手势事件
  // ……
};
```

常用调整：

- **嫌课件翻得慢**：`docBoost` 从 `12` 提到 `20~30`（翻太快有漏渲染风险）
- **倍速被锁**：某些课锁了倍速，脚本会退回原速并提示 `本课程可能锁了倍速，已按原速播`
- **不想要面板**：`panel: false`

## 工作原理

```
读右侧目录  ──→  定位当前节点  ──→  判断节点类型
                                      │
                          ┌───────────┴───────────┐
                          │                       │
                       有 video              无 video
                          │                       │
                    点播放 / 保活          推进课件（秒过）
                          │                       │
                    视频播完 ──→ 补推本节课件 ──→ 目录确认完成？
                                                  │
                                     ┌────────────┴────────────┐
                                     │                         │
                                   是 ↓                       否 ↓
                                下一节（四层保险）        原地继续 / 记「需人工」
```

几个关键设计：

- **目录确认是闸门**：课件推到底但目录说没完成，就原地继续，不会像早期版本那样判定「读完」就飞走
- **连续推不动的出口**：课件可滚余量小于 `sweepTail`、或内容指纹连续 `sweepStillMax` 次不变，才判定到底
- **内容指纹**：判据不只看 `scrollTop`（翻页式阅读器根本不改它），还看文本长度、图片数、子元素滚动位置、首尾图 `src`
- **Sweep 上限**：单节点最多 `sweepMax` 次有效推进，防死循环

## 版本历史

| 版本 | 主要变化 |
|---|---|
| v6 | 课件推进间隔 7000 → 2400 ms（原来 7 秒/屏太慢） |
| v7 | **视频播完继续补推本节课件**；修复「有视频的节点，下方 PPT 永远停在第 1 页」 |
| v7.1 / v7.2 | 修正推进计数单位（从「tick 轮数」改成「真推进次数」）；补「连续推不动」出口 |
| v7.3 | **课件秒过**：先按 `End` 一键到底，再连发滚轮 + PageDown；节流 2400 → 1200 ms |
| v7.4 | 按钮语义拆清（暂停 / 停用 / 下一节）；去掉「秒过/逐屏」切换开关，秒过固定开启 |
| v7.5 | **动作状态机** —— 状态栏改为实时显示真实动作，修复「状态不实时」（判定优先级排错，`nodeDone` 把视频状态永久吞掉） |
| v7.6 | 标题改**三色指示灯**；状态栏只剩一行彩色大字铺满整栏；上下文信息移入进度行 |

## 常见问题

**Q：面板显示「推进课件中」但 PPT 没动？**
点「📋 诊断」，把报告贴到 issue。里面含每个目录项的真实 class、`onclick`、屏幕坐标、`chapterId` 序列，能定位是识别失败还是推进失败。

**Q：倍速点不上去？**
有些课程锁了倍速，脚本会退回原速并在面板提示。这是服务端限制。

**Q：会不会被检测？**
脚本只在页面内操作 DOM，发的是和手工点击完全一样的页面事件，不改请求、不改作业答案、不伪造进度上报。

**Q：中途想停？**
点 `⏸ 暂停`（可恢复）或右上 `✕`（停用，需刷新页面恢复）。
